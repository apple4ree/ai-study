# 자료구조는 저장 방식과 연산의 약속이다

문서 100만 개의 ID를 보관한다고 하자. “ID가 있는지 확인한다”, “시간순으로 가장 오래된 ID를 뺀다”, “우선순위가 가장 높은 ID를 고른다”는 서로 다른 요청이다. 모두 같은 리스트로 구현할 수 있지만 필요한 연산 비용은 크게 달라진다. 자료구조를 선택한다는 것은 데이터를 어떻게 저장하고, 어떤 연산을 빠르게 하며, 그 대가로 무엇을 부담할지 정하는 일이다. 먼저 자주 하는 연산과 보장해야 할 순서를 적은 뒤 구조를 고르는 것이 출발점이다.

## 추상 자료형과 복잡도

스택·큐·집합·맵은 사용할 수 있는 연산과 의미를 정하는 추상 자료형이다. 예를 들어 맵은 키에 대응하는 값을 저장·조회·삭제하는 약속이다. 맵을 해시 테이블로 만들 수도, 균형 탐색 트리로 만들 수도 있다. 사용자는 같은 조회 연산을 호출해도 내부 저장 방식과 정렬 순서·최악 비용이 달라진다. 인터페이스의 의미와 구현의 성질을 분리해야 라이브러리 선택을 정확히 할 수 있다.

시간복잡도는 입력 크기 n이 커질 때 일이 어떻게 증가하는지 나타낸다. O(1)은 n에 비례해 늘지 않는다는 뜻이지 실제로 한 번의 CPU 명령만 실행한다는 뜻이 아니다. O(n)은 원소 수에 비례하는 일을 하고, O(log n)은 후보를 일정 비율씩 줄이는 과정에서 자주 나타난다. 엄밀하게 O는 점근적 상한이고, 위아래가 같은 차수로 묶인다는 것을 명시할 때는 Θ를 쓴다. 예를 들어 항상 3n+2번의 기본 연산을 하면 Θ(n)이며 O(n²)라는 느슨한 상한도 논리적으로 참이다. 일반적인 설명에서 “O(n)”이라고 말할 때는 유용한 가장 타이트한 수준을 의도하는 경우가 많으므로 상한과 정확한 증가 수준을 구분한다. 실제 시간에는 상수, 원소 처리 비용, 메모리 접근, 언어·컴파일러가 영향을 준다.

위 곡선은 n, log₂n, n log₂n, n² 같은 **가정한 연산 수의 증가 형태**를 비교하는 그림이다. 세로축을 실제 초 단위로 읽으면 안 된다. 작은 입력에서 어떤 구현이 더 빠른지는 이 그림만으로 알 수 없지만 n이 커질 때 제곱 증가가 얼마나 빨리 부담이 되는지는 볼 수 있다. 같은 알고리즘도 평균·최악·분할상환 중 무엇을 표시했는지 확인해야 한다.

## 배열: 위치를 계산해서 접근한다

고정 크기 원소가 연속해서 저장된 배열에서는 i번째 원소의 위치를 시작 주소+i×원소 크기로 계산할 수 있다. 그래서 유효 인덱스의 접근은 O(1)이다. 반면 중간에 원소를 끼워 넣으면서 순서를 보존하려면 뒤 원소를 밀어야 한다. `[10,20,30,40]`의 인덱스 1에 15를 넣는다면 40,30,20을 한 칸씩 옮긴 뒤 15를 저장한다. 필요한 이동량은 위치에 따라 달라지고 최악에는 O(n)이다.

동적 배열은 현재 원소 수와 확보한 용량을 구분한다. 공간이 남으면 끝에 쓰기만 하면 되지만 용량이 꽉 차면 더 큰 영역을 확보하고 기존 원소를 옮겨야 한다. 용량을 1,2,4,8처럼 두 배로 늘린다고 가정하면 비싼 복사 작업이 가끔 생긴다. n번 append 동안 옮기는 양의 합은 1+2+4+…로 총 O(n)이므로 한 연산당 분할상환 비용은 O(1)이다. 매 append가 상수 시간이라는 말이 아니라 **연산열 전체 비용을 나누었을 때** 그렇다는 뜻이다.

CPython의 일반적인 list는 객체 참조의 동적 배열이다. 리스트의 참조 슬롯이 연속하다고 해서 각 Python 정수 객체의 내용도 C 정수 배열처럼 연속이라는 뜻은 아니다. 숫자 대량 연산에 NumPy의 고정 dtype 배열을 쓰면 저장 밀도와 연속 연산 방식이 달라지는 이유가 여기에 있다. 두 컨테이너의 원소 수만 비교해서 실제 메모리 사용량이 같다고 생각하면 안 된다.

## 연결 리스트: 다음 주소를 따라간다

연결 리스트의 각 노드는 값과 다음 노드를 가리키는 참조를 가진다. 노드들이 메모리에서 이웃할 필요는 없다. 첫 노드에서 출발해 next를 반복해서 따라가면 전체를 읽을 수 있다. i번째 노드를 바로 계산해 찾을 수 없으므로 일반적인 인덱스 접근은 O(n)이다. 대신 삽입 위치의 앞 노드 p를 이미 알고 있다면 새 노드의 next를 [p.next](http://p.next)로 연결하고 [p.next](http://p.next)를 새 노드로 바꾸는 상수 번의 수정으로 삽입한다.

```py
class Node:
    def __init__(self, value, next=None):
        self.value = value
        self.next = next

head = Node(10, Node(30))
new = Node(20, head.next)
head.next = new
```

처음에는 10 노드가 30 노드를 가리킨다. 새 노드는 30을 가리키게 만들고, 마지막 줄에서 10이 20을 가리키게 한다. 결과 순서는 10,20,30이다. 연결을 바꾸는 순서가 중요하다. 기존 다음 노드를 잃어버린 뒤 연결하려 하면 뒤쪽 목록에 도달하지 못할 수 있다. 노드 추가 자체의 O(1) 비용과 위치를 찾는 O(n) 비용을 합쳐 생각해야 한다.

이중 연결 리스트는 이전 노드 참조도 가져 양방향 이동과 주어진 노드 삭제에 유리하다. 대신 노드당 저장 공간과 연결 수정 수가 늘어난다. 연결 리스트는 “삽입이 많으면 항상 더 빠르다”는 도구가 아니다. 작은 노드를 따로 할당하는 비용, 캐시 지역성, 위치 탐색 방식에 따라 연속 배열이 더 빠를 수 있다. 빅오는 저장 구조의 물리적 차이를 모두 표현하지 않는다.

## 스택과 큐: 꺼내는 순서를 제한한다

스택은 가장 나중에 넣은 원소를 먼저 꺼내는 LIFO 구조다. push로 넣고 pop으로 꺼낸다. 함수 호출 상태, 괄호 검사, DFS의 미완료 작업을 다룰 때 이런 순서가 맞는다. 동적 배열 끝을 사용하면 push는 분할상환 O(1), pop은 보통 O(1)로 구현할 수 있다. 재귀 호출도 실행 중인 함수가 끝나야 호출자로 돌아가는 중첩 구조를 가지므로 스택이라는 개념과 연결된다. 자료구조로 직접 만든 스택과 시스템의 호출 스택은 같은 원리를 공유하지만 같은 저장 대상은 아니다.

큐는 먼저 들어온 원소를 먼저 꺼내는 FIFO 구조다. 작업 대기열과 BFS에서 사용한다. 배열의 맨 앞을 매번 삭제하면서 나머지를 이동하면 dequeue가 O(n)이 된다. 앞 원소를 지우는 대신 읽을 시작 위치를 이동하는 방법을 쓰면 이동을 피할 수 있다. Python의 `list.pop(0)` 대신 `collections.deque.popleft()`를 쓰는 대표적인 이유다.

원형 버퍼는 고정 크기 배열의 끝에 도달하면 인덱스를 0으로 되돌려 남은 공간을 재사용한다. 용량 4에서 head=2, size=2라면 원소는 인덱스 2와 3에 있다고 하자. 다음 삽입 위치는 (head+size)%4=0이다. 그 위치에 원소를 하나 넣으면 size는 3이 된다. 이어서 앞 원소를 하나 꺼내면 head는 3이 되고 size는 다시 2가 된다. 배열의 실제 위치와 논리적 순서가 다르지만 head·size로 대응을 계산한다. empty와 full을 구분하려면 size를 저장하거나 슬롯 하나를 비우는 등 명확한 규칙이 필요하다.

Deque는 양쪽 끝에서 넣고 뺄 수 있는 구조다. 이중 연결 리스트나 원형 배열 등으로 구현할 수 있다. Python deque도 구체적인 블록 기반 구현을 가지며 단순한 한 줄 배열과 동일하지 않다. 중요한 것은 양끝 연산에 적합하다는 의미와 임의 인덱스 탐색이 배열처럼 항상 O(1)은 아니라는 성질이다.

## 해시 테이블: 키를 저장 위치의 후보로 바꾼다

맵에서 문자열 키를 조회하려면 모든 키를 순회할 수도 있지만 원소가 많아지면 비싸다. 해시 테이블은 키를 해시값으로 변환하고 이를 버킷 위치에 연결한다. 용량이 4인 간단한 예에서 `key % 4`를 쓴다면 10,14,18은 모두 위치 2로 간다. 이런 충돌은 해시 함수의 출력 범위가 제한되어 있으므로 피할 수 없는 가능성이다. 충돌한 키를 어떻게 구분하고 찾아갈지가 자료구조 설계의 일부다.

Chaining은 각 버킷에 여러 항목의 목록을 두고 실제 키를 비교한다. Open addressing은 테이블 안의 다른 슬롯을 탐사한다. 후자는 빈 슬롯과 삭제한 슬롯의 의미를 구별해야 탐색이 중간에 잘못 멈추지 않는다. 예를 들어 충돌 때문에 뒤 슬롯에 저장한 키를 찾는 도중 앞 슬롯이 삭제되었다고 곧바로 실패를 반환하면 그 키를 놓친다. 삭제 표식이나 적절한 재배치가 필요한 이유다.

적재율 α는 저장한 항목 수를 테이블 용량으로 나눈 값이다. 적재율이 높아지면 충돌과 탐사 비용이 커질 수 있어 용량을 늘리고 위치를 다시 계산한다. 좋은 분산과 적절한 적재율 등 조건 아래 평균 조회·삽입을 O(1)로 설명하지만 최악에는 많은 키를 확인할 수 있다. resize 한 번은 전체 항목을 옮기는 O(n) 작업일 수 있다. 긴 문자열의 해시 계산과 동등성 비교 비용까지 포함하면 “키가 아무리 길어도 언제나 완전히 일정한 시간”은 아니다.

키의 동등성과 해시 일관성도 중요하다. 같다고 판정되는 두 키는 같은 해시값을 가져야 해시 테이블에서 올바르게 찾을 수 있다. 키로 저장한 뒤 해시·동등성 기준이 바뀌는 가변 객체는 문제를 일으킬 수 있다. Python이 list를 기본적으로 dict 키로 허용하지 않는 이유를 이런 관점에서 이해할 수 있다.

## 트리와 이진 탐색 트리: 계층과 순서를 이용한다

트리는 루트에서 자식으로 내려가는 계층을 표현한다. 파일 디렉터리, 구문 구조, 분류 체계처럼 부모·자식 관계가 중요한 데이터에 맞는다. 각 노드의 자식 수, 트리 높이, 균형 여부에 따라 탐색 비용이 달라진다. 이진 트리는 각 노드에 최대 두 자식이 있는 구조일 뿐, 자동으로 탐색 순서가 정해지는 것은 아니다.

이진 탐색 트리, BST는 왼쪽 부분트리의 키가 현재 키보다 작고 오른쪽은 크다는 식의 정렬 불변식을 둔다. 중복 키를 어떻게 다룰지는 별도 계약이다. 키 8에서 3을 찾으면 3\<8이므로 왼쪽으로, 다음 노드가 5라면 다시 왼쪽으로 내려간다. 매 단계 비교 하나로 한쪽 부분트리를 제외한다. 연산 비용은 트리 높이 h에 비례해 O(h)다.

1,2,3,4를 그대로 삽입해 오른쪽으로만 뻗은 BST는 높이가 원소 수에 비례해 최악 O(n)이 된다. 반면 AVL·red-black tree 같은 균형 트리는 회전과 높이·색 규칙으로 높이를 O(log n) 수준으로 유지한다. 회전은 탐색 순서를 보존하면서 부모·자식 연결을 바꾸는 연산이다. 균형을 유지하는 추가 작업을 지불해 최악 탐색을 제어하는 설계다. 정렬 순회나 범위 검색이 필요하면 해시 테이블보다 이런 트리 계열이 적절할 수 있다.

## 힙: 전체 정렬 대신 가장 급한 원소만 보장한다

최소 힙은 부모의 우선순위가 자식보다 크지 않다는 불변식을 유지한다. 완전 이진 트리 형태를 배열로 저장하면 인덱스 i의 자식은 2i+1과 2i+2, 부모는 (i−1)//2로 계산할 수 있다. 루트는 전체 최솟값이므로 확인은 O(1)이다. 하지만 서로 다른 부분트리의 형제·사촌까지 정렬되지는 않으므로 힙 배열을 그대로 읽으면 오름차순 목록이 되지 않는다.

최소 힙 `[2,5,3,9,7]`에 1을 추가하면 먼저 끝에 넣어 `[2,5,3,9,7,1]`이 된다. 부모 3보다 작으므로 교환해 `[2,5,1,9,7,3]`, 다시 부모 2와 교환해 `[1,5,2,9,7,3]`이 된다. 추가 원소가 루트 방향으로 이동한 것이다. 트리 높이만큼만 올라가므로 O(log n)이다. 최솟값을 꺼낼 때는 마지막 원소를 루트로 옮기고 더 작은 자식과 교환하며 내려가 불변식을 복원한다.

우선순위 큐는 이처럼 매번 최우선 항목을 처리하는 작업에 적합하다. Dijkstra의 다음 후보, 이벤트 시뮬레이션, 제한된 상위 k개 유지에 사용한다. 임의의 특정 키를 빨리 찾는 목적이라면 힙만으로 충분하지 않을 수 있고 별도 위치 맵 등이 필요하다. 모든 문제에 힙을 쓰기보다 필요한 연산이 무엇인지 다시 확인한다.

## 그래프: 연결 자체가 데이터일 때

그래프는 대상인 정점과 관계인 간선으로 이루어진다. 추천 관계, 도로, 작업 의존성은 트리보다 일반적인 연결을 가진다. 방향·가중치·중복 간선·자기 간선을 허용할지 먼저 정해야 같은 저장 구조를 일관되게 해석할 수 있다. 그래프는 추상적 관계이고 인접 리스트·인접 행렬은 그 관계를 저장하는 방법이다.

인접 행렬은 V×V 칸에 간선 여부나 가중치를 저장한다. 두 정점의 연결 여부를 바로 확인할 수 있지만 메모리는 O(V²)다. 인접 리스트는 각 정점에 연결된 이웃을 저장해 전체 O(V+E) 공간으로 표현할 수 있다. 이웃 순회에는 적합하지만 두 특정 정점의 연결 검사는 해당 이웃 목록을 훑거나 추가 집합 구조를 써야 한다. 정점 1만 개에 간선이 2만 개 정도인 희소 그래프라면 모든 쌍을 저장하는 것과 실제 연결만 저장하는 것의 차이가 크다.

예를 들어 A가 B,C와 연결되고 B가 C와 연결되었다면 `{A:[B,C], B:[C], C:[]}`는 방향 그래프의 인접 리스트다. 무방향 관계라면 반대 방향도 저장해야 한다. BFS·DFS는 이 목록을 따라 이웃을 방문한다. 방문 표시를 하지 않으면 순환 그래프에서 같은 정점을 계속 처리할 수 있다. 저장 의미와 알고리즘의 가정이 맞아야 한다.

## 핵심 정리

자료구조는 자주 필요한 연산과 불변식을 기준으로 선택한다. 배열의 인덱스 계산과 연결 리스트의 참조 추적은 서로 다른 비용 구조를 가진다. 스택·큐·Deque는 꺼내는 순서를 정의하며 실제 구현은 여러 방식이 가능하다. 해시 테이블의 빠른 평균 조회는 충돌 처리·분산·적재율이라는 조건에 기대고 있다. BST는 높이, 힙은 부모·자식 불변식이 성능과 기능을 결정한다. 그래프에서는 연결의 의미와 저장 표현을 나누어 생각해야 한다. 복잡도·메모리·실측 시간은 관련되지만 같은 양은 아니다.
