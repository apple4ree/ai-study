# 이산수학은 프로그램의 조건과 구조를 표현하는 언어다

검색 결과가 정렬되어 있다는 조건 아래 이진탐색을 실행한다고 하자. 테스트 몇 개에서 원하는 위치가 나왔다는 사실만으로 모든 입력에서 맞는다고 말할 수는 없다. 배열이 비었거나 같은 값이 반복되거나 찾는 값이 없을 때도 논리가 유지되는지 확인해야 한다.

이산수학은 이런 주장을 명제와 집합, 관계, 그래프, 증명으로 다루는 도구다. 여기서 이산이라는 말은 대상이 연속적인 모든 실숫값으로 움직이기보다 정수·논리값·정점처럼 구별 가능한 구조로 주어진다는 뜻이다.

## 명제의 참과 조건문의 의미

### 개념과 작동 원리

명제는 참 또는 거짓을 판단할 수 있는 문장이다. “배열의 길이가 10이다”는 특정 배열이 정해지면 명제가 된다. AND는 두 조건이 모두 참일 때, OR는 하나 이상 참일 때 참이다. NOT은 참·거짓을 뒤집는다. 프로그래밍의 `if` 조건은 이런 논리 조합을 실제 계산으로 평가한다. 다만 언어가 조건을 왼쪽부터 평가하고 중간에 멈추는 단락 평가를 한다면 부수효과가 있는 함수 호출 순서까지 고려해야 한다.

함의 P→Q는 “P가 성립하면 Q가 성립한다”는 뜻이다. P는 Q의 충분조건이고 Q는 P의 필요조건이다.

예를 들어 “4의 배수이면 짝수다”는 참이지만 “짝수이면 4의 배수다”는 거짓이다. 원래 명제의 역과 원래 명제가 같은 것은 아니다.

반면 “짝수가 아니면 4의 배수가 아니다”라는 대우는 원래 명제와 동치다. 가정이 거짓인 경우의 함의도 논리적으로 참으로 취급한다는 점은 일상 언어의 인과 주장과 다를 수 있다.

함의만으로 시간 순서나 원인을 주장하지 않는다.

요구사항에는 수량을 나타내는 표현이 자주 들어간다. “모든 요청에는 ID가 있다”는 전칭 명제이고 “오류가 난 요청이 하나 이상 있다”는 존재 명제다. 전칭 명제를 부정하면 존재 명제가 된다. “모든 요청이 성공한다”의 부정은 “모든 요청이 실패한다”가 아니라 “실패하는 요청이 하나 이상 있다”다. 이런 차이는 테스트의 반례를 무엇으로 정의할지 결정한다.

| 주장 | 정확한 부정 |
| --- | --- |
| 모든 x에서 f(x)>0 | f(x)≤0인 x가 하나 이상 있다 |
| 성공한 요청이 하나 이상 있다 | 성공한 요청이 하나도 없다 |
| P와 Q가 모두 성립한다 | P가 아니거나 Q가 아니다 |

### 조건의 방향과 양화사의 순서를 표로 확인하기

| 주장 | 뜻 | 일반적으로 동치인가 |
|---|---|---|
| P→Q | P이면 Q | 원래 주장 |
| Q→P | Q이면 P | 역: 원래 주장과 다를 수 있음 |
| ¬Q→¬P | Q가 아니면 P도 아님 | 대우: 원래 주장과 동치 |
| ¬P→¬Q | P가 아니면 Q도 아님 | 이: 원래 주장과 다를 수 있음 |

“각 사용자에게는 접근할 수 있는 문서가 적어도 하나 있다”는 $\forall u\,\exists d\,A(u,d)$다. 사용자마다 문서가 달라도 된다. “모든 사용자가 접근할 수 있는 문서가 적어도 하나 있다”는 $\exists d\,\forall u\,A(u,d)$로 더 강한 조건이다.

**양화사 순서를 바꾸면 요구사항이 달라진다.** 첫 주장의 부정은 $\exists u\,\forall d\,\neg A(u,d)$다. 즉 접근할 수 있는 문서가 전혀 없는 사용자가 적어도 하나 있다는 뜻이다.

Python의 `x != 0 and 10/x > 2`는 왼쪽이 거짓이면 나눗셈을 평가하지 않는다. 논리적 진리표와 실제 **단락 평가 순서**를 함께 이해해야 한다. [언어 공식 명세](https://docs.python.org/3/reference/expressions.html#boolean-operations)는 and/or가 피연산자 값을 반환할 수 있음도 설명한다.

## 집합, 함수, 관계로 데이터의 의미를 정한다

### 개념과 작동 원리

집합은 원소의 모임이며 보통 순서와 중복을 구별하지 않는다. 리스트 `[a,a,b]`와 집합 `{a,b}`는 저장 의미가 다르다. 합집합은 한쪽 이상에 있는 원소, 교집합은 양쪽에 있는 원소, 차집합은 한쪽에만 남는 원소다. 문서 검색에서 키워드 두 개를 모두 포함하는 문서를 찾는 것은 문서 ID 집합의 교집합으로 표현할 수 있다. 문제를 집합 연산으로 적으면 구현의 순서·중복 제거가 의미를 바꾸는지 점검하기 쉽다.

함수 f:A→B는 A의 각 원소에 B의 원소 하나를 대응시킨다. 함수의 입력 범위와 출력 범위를 명시하는 이유는 허용되지 않은 입력과 결과를 구분하기 위해서다.

일대일 함수는 서로 다른 입력이 같은 출력으로 합쳐지지 않는다. 전사 함수는 B의 모든 원소가 적어도 하나의 입력에서 나온다.

역함수를 하나의 함수로 만들려면 적절한 범위에서 일대일 대응이 필요하다. 해시 함수는 보통 매우 많은 입력을 제한된 정수 범위로 보내므로 전체 입력에서 일대일일 수 없다.

관계는 두 대상 사이의 조건이다. “같은 길이의 문자열이다”는 동치관계를 만든다.

동치관계는 자기 자신과 관계가 있고, 방향을 바꾸어도 같으며, 두 관계를 이어도 유지된다. 이를 이용하면 원소를 겹치지 않는 동치류로 나눌 수 있다.

Union-Find는 연결되어 같은 집합에 속하는지를 관리하는 자료구조로 이어진다. 반면 “작업 A가 B보다 먼저 끝나야 한다”는 모든 쌍이 비교되는 관계가 아닐 수 있다.

독립된 작업 둘은 어느 쪽을 먼저 해도 되므로 전체 순서가 아니라 부분순서로 생각하는 것이 자연스럽다.

### 함수의 일대일·전사와 중복 제거

A={a,b,c}, B={1,2}이고 f(a)=1, f(b)=1, f(c)=2라 하자. 모든 입력의 결과는 하나로 정해져 있으므로 함수다. 하지만 a와 b가 같은 결과를 가지므로 일대일은 아니고, B의 두 원소가 모두 나타나므로 전사다.

| 성질 | 검사할 조건 | 데이터 처리 해석 |
|---|---|---|
| 함수 | 각 입력에 결과 하나 | 키마다 반환 의미가 정해짐 |
| 단사 | 다른 입력은 다른 결과 | 결과에서 입력을 유일하게 구분 가능 |
| 전사 | 공역의 모든 원소가 결과로 나옴 | 정의한 결과 범위를 모두 사용 |
| 전단사 | 단사이면서 전사 | 역함수가 존재 |

집합으로 바꾸면 `[a,a,b]`의 중복 개수 정보가 사라진다. 수학적 집합의 중복 없음과 프로그래밍 컨테이너의 순회 순서는 다른 주제다. 중복 제거 후 순서가 필요하면 그 조건을 별도로 명세해야 한다.

'같은 그룹'을 정의할 때 동치관계가 필요한 이유도 여기에 있다. 임계거리 이내라는 관계는 반사·대칭이어도 추이적이지 않을 수 있으므로 자동으로 동치류를 만들 수 있는 것은 아니다.

## 증명은 가정과 결론 사이를 빠짐없이 잇는다

### 개념과 작동 원리

직접증명은 가정에서 정의와 이미 아는 성질을 적용해 결론에 도달한다. 짝수 n은 어떤 정수 k에 대해 n=2k이므로 n²=4k²=2(2k²)도 짝수다. 모순을 이용하는 증명은 결론이 거짓이라고 가정했을 때 앞의 조건과 양립할 수 없는 결과를 보인다. 대우 증명은 P→Q 대신 ¬Q→¬P를 증명한다. 방법은 달라도 어떤 대상을 가정했고 무엇을 보였는지는 분명해야 한다.

수학적 귀납법은 자연수 크기마다 주장을 이어가는 방법이다. 1+2+…+n=n(n+1)/2를 보자. n=1에서 양쪽이 1이다. 어떤 n에서 식이 맞는다고 가정하면 n+1까지의 합은 n(n+1)/2+(n+1)=(n+1)(n+2)/2가 된다. 따라서 다음 크기에서도 식이 맞는다. 기초 단계가 없으면 시작하지 못하고 귀납 단계가 없으면 다른 크기로 넘어가지 못한다. “몇 개 대입해 보니 같다”는 이 두 단계를 대신하지 못한다.

강한 귀납법은 n보다 작은 모든 크기의 성질을 사용할 수 있게 한다. 재귀 알고리즘이 문제를 n−1 하나가 아니라 여러 더 작은 문제로 나눌 때 유용하다. 다만 작은 문제의 정답을 가정하는 것과 작은 문제를 실제로 계산하는 것은 다르다. 전자는 정확성 논증이고 후자는 구현·실행 과정이다. 이 둘을 섞으면 “재귀 호출이 있으니 맞다”는 순환 설명이 되기 쉽다.

### 귀납 가정의 범위와 기저 사례 검증

모든 n≥0에 대해 $\sum_{i=1}^{n}i=n(n+1)/2$임을 보이자. 빈 합을 0으로 정의하면 n=0에서도 성립한다.

1. **기저:** n=0에서 양쪽이 0이다.
2. **가정:** 임의의 n에서 합이 n(n+1)/2라고 가정한다.
3. **전개:** 다음 합은 기존 합에 n+1을 더한 것이다.
4. **정리:** $n(n+1)/2+(n+1)=(n+1)(n+2)/2$다.

귀납 가정은 아직 증명하지 않은 임의의 결론을 마음대로 써도 된다는 허가가 아니다. 기저와 전달 단계가 연결되어 모든 허용 크기를 덮어야 한다.

**확인 문제:** n=2가 짝수이고, 짝수 n에서 n+2도 짝수임을 보였다. 모든 양의 정수가 짝수라고 증명한 것인가?

## 반복문 불변식과 종료를 나누어 확인하기

### 개념과 작동 원리

불변식은 반복이 진행되어도 정해진 시점에 계속 성립하는 조건이다. 합 계산을 예로 들면 반복 시작 시 total이 이미 처리한 앞 구간의 합이라는 조건을 둘 수 있다.

```py
total = 0
for i in range(len(xs)):
    total += xs[i]
```

처음에는 처리한 원소가 없고 합은 0이므로 조건이 맞다. i번째 반복에서 xs\[i\]를 더하면 처리 구간이 한 칸 늘어나고 다음 반복의 조건도 맞다. 모든 원소를 처리한 뒤에는 total이 전체 합이다. 이 논증은 빈 리스트에서도 초기값 0을 그대로 반환하는 행동까지 설명한다. 여기서 불변식은 “total이 커진다”가 아니다. 음수가 있으면 합이 작아질 수 있어도 앞 구간의 합이라는 정확한 관계는 유지된다.

불변식은 종료했을 때의 정답을 보이는 데 쓰이지만 반복이 반드시 끝난다는 사실은 별도로 확인해야 한다. 유한한 리스트의 for문은 반복 횟수가 정해져 있다. while문에서는 남은 후보 구간 길이처럼 음수가 되지 않고 매번 감소하는 척도를 찾을 수 있다. 감소하지 않는 분기가 하나라도 있으면 무한 반복 가능성을 살펴야 한다. 정확성과 종료를 합쳐야 전체 알고리즘이 원하는 입력에 대해 올바르게 끝난다고 말할 수 있다.

```py
def gcd(a, b):
    while b != 0:
        a, b = b, a % b
    return a
```

양의 정수에서 gcd(a,b)=gcd(b,a mod b)이므로 최대공약수라는 값은 반복 전후에 보존된다. 동시에 다음 b는 이전 b보다 작은 음이 아닌 나머지다. 예를 들어 (18,12)→(12,6)→(6,0)으로 줄고 종료 값은 6이다. 이 예제는 “보존되는 성질”과 “작아지는 값”이 서로 다른 역할을 한다는 것을 보여 준다.

### 최댓값 순회의 정확성과 종료를 분리하기

비어 있지 않은 리스트 xs에서 다음 코드는 지금까지 본 최댓값을 유지한다.

```py
def maximum(xs):
    if not xs:
        raise ValueError('nonempty input required')
    best = xs[0]
    for i in range(1, len(xs)):
        best = max(best, xs[i])
    return best

assert maximum([-7, -2, -5]) == -2
```

| 시점 | 불변식의 뜻 |
|---|---|
| 시작 | 첫 원소 하나의 최댓값이 best |
| i 처리 전 | best는 xs[0:i]의 최댓값 |
| i 처리 후 | 새 원소와 비교하여 xs[0:i+1]의 최댓값 |
| 종료 | 전체 구간의 최댓값이 best |

각 반복에서 남은 원소 수가 하나 줄어 **종료**하며, 불변식이 반환값의 **정확성**을 보인다. 비교가 O(1)이라는 가정 아래 시간 O(n), 추가 공간 O(1)이다. best=0으로 시작하면 전부 음수인 입력에서 틀리므로 초기화도 증명의 일부다.

## 세기와 비둘기집 원리

### 개념과 작동 원리

두 선택을 차례로 할 때 첫 선택이 a가지이고 각 경우 둘째 선택이 b가지라면 전체는 ab가지다. 서로 겹치지 않는 선택지를 합치면 경우의 수는 더한다. 순열은 순서를 구별하고 조합은 선택 집합만 구별한다. 사용자 5명 중 발표자 2명의 순서를 정하면 5×4=20가지지만 단순히 2명을 고르면 10가지다. 순서를 문제에서 구별하는지에 따라 계산이 달라진다.

비둘기집 원리는 n+1개 대상을 n개 상자에 넣으면 어떤 상자에는 둘 이상 들어간다는 사실이다. 해시 값이 0\~7의 8가지뿐이라면 서로 다른 키 9개를 모두 다른 값에 보낼 수 없다.

충돌은 구현을 잘못해서 생기는 예외가 아니라 제한된 출력 범위에서 필연적으로 가능한 현상이다. 따라서 해시 테이블은 좋은 해시 함수와 함께 충돌 처리 규칙이 필요하다.

모든 키가 고르게 흩어진다는 가정 아래의 평균 성능과 실제 최악 상황을 구분해야 한다.

확률도 원소를 세는 방법과 이어지지만 균등한 경우인지 먼저 확인해야 한다. 가능한 결과가 8개라고 해서 언제나 각각의 확률이 1/8은 아니다. 해시 함수의 출력 개수만으로 실제 키 분포가 균등하다고 결론 내릴 수 없다. 이산수학의 세기와 공학 수학의 확률론을 함께 사용할 때 가정을 먼저 적는 이유다.

서로 겹치는 집합의 크기를 더할 때는 중복을 빼야 한다. 문서 10개가 키워드 A를, 8개가 B를 포함하고 그중 3개가 둘 다 포함하면 한쪽 이상을 포함한 문서는 10+8−3=15개다. 교집합 3개를 두 번 셌기 때문에 한 번 빼는 포함·배제 원리다. 데이터 집계에서 중복 ID를 처리하지 않고 행 개수만 더했을 때 실제 사용자·문서 수가 부풀려지는 이유를 수학적으로 설명한다.

경우의 수를 세는 것은 탐색 비용을 예상하는 데도 쓰인다. 원소 n개를 각각 선택하거나 선택하지 않으면 부분집합은 2ⁿ개다. n=10이면 1,024개지만 n=30이면 약 10억 개다. 완전탐색이 작은 문제에서 좋은 정답 검증기여도 큰 문제에서는 어려워지는 이유다. 단순히 “재귀니까 느리다”가 아니라 어떤 상태를 몇 개 방문하는지 세어야 한다.

### 순서·중복 허용 여부에 따라 세기

서로 다른 후보 5명에서 2명을 뽑는다고 하자.

| 조건 | 계산 | 결과 |
|---|---|---|
| 회장·부회장, 겸임 불가 | 5×4 | 20 |
| 역할 없는 2인 팀 | 5×4/2! | 10 |
| 두 자리에 같은 후보 허용 | 5×5 | 25 |

순서가 없는 팀에서 2!로 나누는 이유는 같은 팀을 두 순서로 셌기 때문이다. 반복이 허용된 대상을 무조건 같은 팩토리얼로 나누면 각 결과의 중복 횟수가 달라질 수 있다.

비둘기집 원리는 결과의 **존재 보장**이다. 해시 출력 8종류에 서로 다른 입력 9개를 넣으면 충돌은 반드시 있지만, 어떤 입력이 충돌하는지·충돌 쌍이 몇 개인지·출력이 균등한지는 정하지 못한다.

**복습 문제:** 서로 다른 키 8개를 8개 해시값에 넣으면 충돌이 반드시 없는가?

<details><summary>풀이</summary>

아니다. 모두 다른 값에 들어갈 수도 있고 일부가 같은 값에 들어갈 수도 있다. 9개를 넣을 때는 충돌이 보장되지만 그 역으로 8개 이하면 충돌이 없다는 주장은 따라오지 않는다.

</details>

## 점화식과 그래프는 재귀·의존관계를 드러낸다

### 개념과 작동 원리

입력 크기 n인 문제를 절반 크기의 문제 두 개로 나누고 결합에 n만큼 일이 든다면 T(n)=2T(n/2)+n으로 표현할 수 있다. 첫 층의 총 결합 비용은 n, 다음 층은 n/2인 일이 두 개여서 역시 n이다. 크기가 1이 될 때까지 대략 log₂n층이 있으므로 총 비용은 n log n 수준이 된다. 이 계산은 정확한 CPU 시간 예측이 아니라 입력 규모에 따라 필요한 일이 어떻게 증가하는지 설명하는 모델이다.

그래프는 정점과 간선으로 관계를 나타낸다. 방향 그래프에서 A→B는 A에서 B로 가는 관계를 뜻하고, 무방향 그래프에서는 방향을 구분하지 않는다. 경로는 간선을 따라 이어지는 정점의 나열이며, 시작점으로 돌아오는 경로는 순환을 만든다. 트리는 연결되어 있고 순환이 없는 무방향 그래프로 볼 수 있으며 n개 정점의 트리에는 n−1개 간선이 있다. 이 성질은 순환 검사와 트리 재귀를 이해하는 기반이 된다.

작업 “다운로드→정제→학습→평가”와 “다운로드→품질검사→학습”을 생각해보자. 정제와 품질검사는 서로 먼저일 필요가 없지만 학습은 둘이 모두 끝나야 한다. 방향 비순환 그래프, 즉 DAG에서는 이런 선행 조건을 만족하는 위상순서를 만들 수 있다.

평가가 끝나야 다운로드를 시작할 수 있다는 간선을 추가하면 순환이 생겨 모든 선행 조건을 충족할 시작점이 없어질 수 있다. 그래프는 예쁜 그림이 아니라 실행 순서가 가능한지 판단하는 모델이다.

상태 기계는 가능한 상태와 허용 전이를 분리해서 표현한다. 작업 상태를 대기·실행·완료·실패로 정하면 완료 뒤 다시 실행 중으로 바꾸어도 되는지 같은 규칙을 명시할 수 있다. 상태별 불변식을 두고 전이가 이를 보존하는지 확인하면, 조건문을 임의로 추가하는 것보다 예외 경로를 체계적으로 다룰 수 있다.

### 재귀 비용의 층별 합과 의존 그래프

n이 2의 거듭제곱이고 $T(n)=2T(n/2)+n$, $T(1)=1$이라 하자. 깊이 j에는 2ʲ개 부분문제, 각 크기는 n/2ʲ여서 그 층의 결합 작업은 n이다. 내부 층이 log₂n개이고 잎 전체 비용도 n이므로 $T(n)=n\log_2n+n$이다.

**재귀 호출 수와 한 호출의 작업량을 함께 더해야 한다.** 호출 깊이가 log n이라고 전체 시간이 O(log n)인 것은 아니다. 순차 재귀에서 각 프레임이 상수 공간을 쓰면 호출 스택 깊이는 O(log n)이지만, 부분배열을 복사하면 추가 공간 분석이 달라진다.

| 작업 | 선행 조건 |
|---|---|
| 정제 | 다운로드 완료 |
| 품질검사 | 다운로드 완료 |
| 학습 | 정제·품질검사 모두 완료 |
| 평가 | 학습 완료 |

위상정렬은 가능한 실행 순서를 주지만 유일한 순서를 보장하지 않는다. 정제와 품질검사 순서를 바꾸어도 조건을 만족한다. 방향 순환이 있으면 모든 선행 조건을 만족하는 순서는 존재하지 않는다. 인접 리스트·진입차수와 큐를 쓰는 위상정렬은 O(V+E) 시간, 그래프를 포함해 O(V+E) 공간이다.

## 핵심 정리

논리는 프로그램의 조건을 모호하지 않게 표현한다. 집합과 관계는 순서·중복·연결의 의미를 구분하게 한다. 증명은 가정에서 결론까지의 논리적 연결을 보이고 테스트는 구체적 반례를 찾는다. 귀납법과 불변식은 크기가 달라져도 성립하는 알고리즘의 성질을 설명한다. 종료는 보존되는 성질과 별개로 감소하는 척도를 확인해야 한다. 세기·점화식·그래프는 충돌 가능성, 계산량, 작업 의존성을 다루는 공통 언어다.

## 복습문제와 풀이

**문제 1.** “모든 문서가 비어 있지 않다”의 부정은 무엇인가?

<details>
<summary>풀이 보기</summary>

비어 있는 문서가 하나 이상 존재한다는 명제다. 모든 문서가 비었다는 명제는 더 강하며 원래 명제의 단순 부정이 아니다.

</details>

**문제 2.** 최댓값 탐색에서 “현재 값은 지금까지 읽은 원소의 최댓값”이라는 불변식을 쓰려면 무엇을 주의해야 하는가?

<details>
<summary>풀이 보기</summary>

초기값과 빈 입력 계약을 정해야 한다. 첫 원소로 시작하면 비어 있지 않은 리스트라는 가정이 필요하고, 임의로 0에서 시작하면 모든 값이 음수인 입력에서 불변식이 깨진다.

</details>

**문제 3.** 입력 크기 8을 매번 절반으로 나누어 두 하위문제로 풀고 층마다 총 8의 결합 비용이 생긴다. 이런 층이 3개라면 결합 비용은 얼마인가?

<details>
<summary>풀이 보기</summary>

결합 비용은 8×3=24다. 말단 처리 비용은 별도로 더한다. 일반적인 2T(n/2)+n 모델에서 로그 개수의 층에 n씩 일이 생긴다는 관계를 확인한 것이다.

</details>
