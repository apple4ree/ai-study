# 알고리즘은 문제를 줄이면서 정답을 보존하는 방법이다

정렬된 숫자 목록에서 어떤 값 이상인 첫 위치를 찾는 문제와, 도로망에서 가장 짧은 경로를 찾는 문제는 겉모습이 다르다. 하지만 둘 다 정답이 어떤 조건을 만족하는지 정의하고, 필요 없는 후보를 제외하며, 남은 계산이 끝나는지 보장해야 한다. 알고리즘을 안다는 것은 패턴 이름을 떠올리는 것보다 **선택의 근거와 적용 조건을 설명하는 것**에 가깝다. 자료구조는 상태를 저장하고 알고리즘은 그 상태를 어떤 규칙으로 바꿀지 정한다.

## 입력·출력·제약을 먼저 정한다

“중복을 제거한다”는 요청만으로는 정답이 하나로 정해지지 않는다. 원래 순서를 유지해야 하는가, 같은 값의 판정 기준은 무엇인가, 입력을 바꾸어도 되는가를 알아야 한다. “최단 경로”도 간선 비용이 모두 같은지, 음수가 있는지, 시작점 하나인지 모든 쌍인지에 따라 다른 문제다. 구현에 들어가기 전에 허용 입력과 반환 의미, 경계 상황을 계약으로 적는 이유다.

n이 100이면 O(n²)도 충분할 수 있지만 n이 100만이면 비교 횟수 자체가 문제가 될 수 있다. 정답의 정확성, 실행시간, 추가 메모리, 입력을 스트리밍할 수 있는지 같은 제약을 함께 본다. Big-O는 큰 입력에서 지배적인 증가를 설명하고 상수나 실제 장비 성능까지 정하지 않는다. 최악·평균 비용도 구분한다. 평균이 빠르더라도 특정 요청의 긴 지연이 문제인 서비스에서는 최악 조건이 중요할 수 있다.

정확성은 테스트와 증명을 함께 사용해 확인한다. 작은 입력을 완전탐색으로 풀어 최적화 코드와 비교하면 많은 반례를 찾을 수 있다. 하지만 테스트를 통과했다는 사실이 모든 입력의 증명은 아니다. 정답을 보존하는 불변식이나 귀납 논증을 세우고, 코드가 그 논증대로 상태를 바꾸는지 점검한다.

## 정렬은 비교 순서와 저장 순서를 함께 바꾼다

삽입 정렬은 앞 구간이 이미 정렬되어 있다고 두고 다음 원소를 알맞은 위치로 옮긴다. `[3,1,2]`에서 1을 앞 구간에 넣으면 `[1,3,2]`, 다음 2를 넣으면 `[1,2,3]`이다. 거의 정렬된 작은 입력에는 이동이 적을 수 있지만 역순에서는 많은 원소를 밀어 최악 O(n²)이 된다. “정렬”이라는 같은 목표도 입력 구조에 따라 비용이 달라진다.

병합 정렬은 반으로 나누어 각각 정렬한 뒤 작은 쪽 원소를 차례로 꺼내 합친다. 두 정렬 목록 `[1,4]`, `[2,3]`을 합칠 때 1,2,3을 비교해 고르고 마지막 4를 붙이면 된다. 전체 n개를 병합하는 일은 O(n), 재귀 깊이는 O(log n)이므로 총 O(n log n)이다. 대표적인 배열 구현은 병합용 추가 공간을 사용한다. 빠른 증가율을 얻는 대신 메모리와 복사 비용이 생기는 설계다.

퀵 정렬은 기준값 주변으로 작은 값과 큰 값을 나누고 각 부분을 정렬한다. 분할이 고르게 되면 빠르지만, 계속 한쪽에 몰리면 깊이가 n까지 늘어 최악 O(n²)이 될 수 있다. 무작위 기준값이나 다른 전략으로 나쁜 경우를 줄일 수 있으나 어떤 변형이 어떤 보장을 하는지는 따로 확인한다. 비교 기반 정렬에는 일반적인 최악 Ω(n log n) 하한이 있지만 정수의 범위 같은 추가 조건을 쓰는 counting·radix sort는 다른 모델을 활용한다.

안정 정렬은 정렬 키가 같은 원소의 기존 상대 순서를 보존한다. 이름순으로 정렬한 목록을 부서 기준으로 안정 정렬하면 부서 안의 이름순을 유지할 수 있다. 안정성, 제자리 여부, 최악시간은 서로 다른 속성이므로 “빠른 정렬 하나”로 묶어 판단하지 않는다. Python의 정렬도 어떤 키를 계산하고 동등한 키를 어떻게 다루는지 이해하고 사용하는 것이 좋다.

## 이진탐색은 정답이 남은 구간을 절반으로 줄인다

이진탐색은 정렬이라는 조건이 있어야 비교 한 번으로 후보 절반을 버릴 수 있다. 다음 코드는 x 이상인 첫 위치를 반환한다. 구간은 왼쪽 포함·오른쪽 제외인 \[lo,hi)로 둔다.

```py
def lower_bound(a, x):
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < x:
            lo = mid + 1
        else:
            hi = mid
    return lo
```

`a=[1,3,3,7], x=3`에서 상태를 따라가 보자.

| 후보 구간 | mid | 비교 | 다음 구간 |
| --- | --- | --- | --- |
| \[0,4) | 2 | a\[2\]=3이므로 정답이 2 또는 왼쪽 | \[0,2) |
| \[0,2) | 1 | a\[1\]=3이므로 정답이 1 또는 왼쪽 | \[0,1) |
| \[0,1) | 0 | a\[0\]=1은 x보다 작음 | \[1,1) |

lo보다 왼쪽은 x보다 작고 hi 이상은 x 이상이라는 구분을 유지한다. 후보가 없어지면 그 경계가 답이다. 모든 값이 x보다 작으면 len(a)를 반환하며 이것은 유효 원소 인덱스가 아니라 삽입 위치다. `mid+1`과 `hi=mid`의 차이는 현재 mid가 정답일 가능성을 남겨야 하는지에서 나온다. 경계 규칙을 이해하지 않고 외우면 중복·빈 배열에서 틀리기 쉽다.

배열이 아니라 답의 수치 범위에도 이진탐색을 쓸 수 있다. 어떤 작업을 시간 T 안에 끝낼 수 있으면 더 긴 시간에도 가능하다는 단조성이 있다면 “가능한 최소 T”를 찾을 수 있다. 가능한지 판정하는 함수의 비용까지 전체 복잡도에 포함해야 한다. 단조성이 없는데 후보를 절반씩 버리면 정답을 놓친다.

## 투 포인터와 슬라이딩 윈도는 되돌아가지 않는 움직임을 이용한다

정렬 배열에서 두 수의 합을 찾을 때 가장 작은 값과 큰 값에서 시작한다. 합이 목표보다 작으면 작은 쪽을 오른쪽으로 움직여 합을 늘리고, 크면 큰 쪽을 왼쪽으로 움직인다. 정렬 덕분에 어떤 후보를 버려도 되는지 알 수 있다. 각 포인터가 한 방향으로만 최대 n번 움직이면 반복문이 중첩되어 보여도 전체 이동은 O(n)이다.

슬라이딩 윈도는 연속 구간의 정보를 유지하면서 한쪽에서 추가하고 다른 쪽에서 제거한다. 길이 k의 합을 매번 새로 계산하면 O(nk)이지만 다음 합=이전 합−나간 값+들어온 값으로 갱신하면 O(n)이다. 합계뿐 아니라 문자별 빈도·중복 수를 유지하는 식으로 상태를 확장할 수 있다. 중요한 것은 현재 구간을 표현하는 상태가 정확히 갱신된다는 점이다.

가변 길이 윈도에서는 조건의 단조성을 특히 주의한다. 모든 값이 음이 아니면 오른쪽을 늘릴 때 합이 줄지 않지만 음수가 섞이면 이 성질이 깨진다. “합이 크면 왼쪽을 줄인다”는 규칙을 모든 부분합 문제에 적용할 수 없는 이유다. 언제 한 후보를 영구히 제외해도 되는지 설명되지 않으면 다른 방법을 찾아야 한다.

## 그리디는 지역 선택이 전체 정답을 보존할 때만 맞다

그리디는 현재 가장 좋아 보이는 선택을 확정하고 되돌리지 않는 방식이다. 종료 시간이 빠른 회의부터 고르는 회의 선택 문제를 보자. 어떤 최적 해의 첫 회의가 우리가 고른 가장 이른 종료 회의보다 늦게 끝난다면 이를 더 일찍 끝나는 회의로 바꾸어도 뒤에 넣을 수 있는 회의 수를 줄이지 않는다. 이런 교환 논증이 지역 선택을 정당화한다.

동전 \[1,3,4\]로 금액 6을 만들 때 큰 동전부터 고르면 4+1+1로 3개다. 하지만 3+3은 2개다. 그리디는 흔히 맞아 보이는 규칙일 뿐, 문제 구조의 근거 없이 자동으로 정답이 되지 않는다. 반례는 작은 입력에서 잘 드러나므로 완전탐색과 비교해보는 것이 유용하다. 다만 반례를 못 찾았다는 사실도 증명과 같지는 않다.

그리디가 맞는 경우에는 DP보다 상태가 적고 구현·실행이 간단할 수 있다. 하지만 이점만 보고 먼저 선택하지 않는다. 교환해도 목적값을 악화시키지 않는지, 남은 문제가 같은 형태로 유지되는지 확인한다. 정렬 기준도 “가장 짧은 회의”, “가장 일찍 시작하는 회의”, “가장 일찍 끝나는 회의”가 서로 다르므로 정확히 명시한다.

## 동적 계획법은 같은 하위문제의 답을 재사용한다

DP의 핵심은 미래 판단에 필요한 정보를 상태로 정하고, 그 상태의 답을 더 작은 상태에서 계산하는 것이다. 상태 정의가 모호하면 점화식을 외워도 변형 문제에 적용하기 어렵다. 계단을 1칸 또는 2칸씩 올라 n칸에 도달하는 방법 수 f(n)을 보자. 마지막 이동이 1칸이면 f(n−1), 2칸이면 f(n−2)가지이고 두 경우는 겹치지 않는다. 따라서 f(n)=f(n−1)+f(n−2)다.

```py
def ways(n):
    if n < 0:
        return 0
    prev, cur = 1, 1  # f(0), f(1)
    if n == 0:
        return prev
    for step in range(2, n + 1):
        prev, cur = cur, prev + cur
    return cur
```

f(0)=1은 아무 이동도 하지 않는 한 가지 방법을 뜻한다. f(1)=1에서 f(2)=2, f(3)=3, f(4)=5로 계산한다. 반복마다 직전 두 답만 필요하므로 전체 배열 대신 두 값으로 공간을 줄였다. Python의 다중 대입은 오른쪽 값을 먼저 평가하므로 갱신 순서가 점화식과 맞는다. 임의 정밀도 정수의 크기 증가까지 고려하면 매우 큰 n의 비트 연산 비용은 단순한 고정 크기 연산 모델과 다를 수 있다.

메모이제이션은 재귀로 필요한 상태를 방문하고 답을 저장하는 top-down 방식이다. Tabulation은 기저 상태부터 정해진 순서대로 채우는 bottom-up 방식이다. 둘 다 같은 하위문제를 중복 계산하지 않는 목적이 있지만 방문하는 상태 수, 재귀 스택, 계산 순서가 다를 수 있다. 배낭 문제처럼 1차원 배열로 압축할 때는 순회 방향이 같은 물건을 여러 번 쓰는지에 영향을 주므로 저장 공간을 줄인 뒤에도 원래 상태 의미를 유지하는지 확인한다.

## 그래프 탐색, 최단경로, 연결 문제

DFS는 한 경로를 깊게 탐색하고 되돌아오는 방식이며 재귀나 명시적 스택으로 구현한다. BFS는 큐를 사용해 시작점에서 간선 수가 적은 순서로 퍼져나간다. 간선 비용이 모두 같은 양수라면 BFS에서 처음 도달한 거리가 최단 거리다. 방문 표시를 언제 하는지도 중요하다. 큐에 넣을 때 표시하지 않고 꺼낼 때만 표시하면 같은 정점을 여러 번 넣어 불필요한 일이 늘 수 있다.

가중치가 다른 경우에는 Dijkstra처럼 현재까지 가장 작은 거리 후보를 먼저 확정하는 방법을 사용한다. 간선 가중치가 음이 아니어야 이미 가장 짧다고 확정한 정점이 나중에 더 짧아지지 않는 논리가 성립한다. 최소 힙을 쓰면 작은 후보를 효율적으로 고를 수 있다. 힙에 낡은 거리 후보가 남는 구현이라면 꺼낸 값이 현재 저장한 최선 거리와 같은지 검사하고 오래된 항목을 건너뛴다.

위상정렬은 DAG에서 선행 조건을 만족하는 순서를 구한다. 진입차수가 0인 정점을 큐에 넣고 처리한 뒤 후속 정점의 진입차수를 줄인다. 남은 정점이 있는데 더 이상 0인 정점이 없으면 순환 가능성을 확인한다. 모든 그래프에 위상순서가 있는 것은 아니다.

최소 신장 트리는 연결된 무방향 가중 그래프의 모든 정점을 총 간선 비용이 최소가 되게 잇는 트리다. 시작점에서 각 정점까지의 최단경로와 목적이 다르다. Kruskal은 간선을 작은 비용순으로 보며 서로 다른 연결 성분을 잇는 간선만 선택한다. Union-Find는 두 정점이 이미 같은 성분인지 빠르게 검사한다. 경로 압축과 rank·size 기반 합치기로 효율을 높인다. 같은 “짧은 연결”이라는 말만 보고 최단경로와 신장 트리를 바꾸어 적용하면 다른 답을 구하게 된다.

## 핵심 정리

알고리즘은 입력 조건, 정답 의미, 불변식, 종료와 비용을 함께 설명해야 한다. 정렬은 비교·분할·병합 방식에 따라 안정성·공간·최악시간이 달라진다. 이진탐색과 투 포인터는 후보를 버려도 되는 단조적 구조가 필요하다. 그리디는 지역 선택을 전체 최적 해와 연결하는 논증이 있을 때 정당하다. DP는 상태·전이·기저·계산 순서를 정확히 정해 중복 계산을 줄인다. 그래프 알고리즘은 방향·가중치·음수·순환 같은 조건에 따라 선택한다. 작은 완전탐색과 경계 입력은 구현을 검증하지만 정확성 설명을 대신하지는 않는다.

<summary>풀이 보기</summary>

각 완성 경로의 마지막 이동은 둘 중 정확히 하나다. 두 경우는 겹치지 않고 모든 경로를 포함하므로 합의 법칙을 적용한다. 하위 상태의 답은 마지막 이동을 붙이기 전의 방법 수다.

</details>

**문제 3.** 간선 수가 적은 경로와 총 비용이 작은 경로가 언제 같은가?

<details>
<summary>풀이 보기</summary>

모든 간선 비용이 같은 양수라면 간선 수를 최소화하는 것이 비용 최소화와 같다. 비용이 다르면 더 많은 간선을 지나도 더 싸질 수 있으므로 BFS의 간선 수 거리만으로는 일반적인 가중 최단경로를 보장하지 못한다.

</details>
