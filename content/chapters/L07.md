## 언어모델은 다음 토큰의 조건부확률을 계산한다

### 개념과 작동 원리

문장 ‘오늘 날씨가’ 다음에는 ‘좋다’, ‘흐리다’처럼 여러 표현이 올 수 있다. 자기회귀 언어모델은 앞선 토큰을 조건으로 다음 토큰의 확률을 계산한다.

전체 토큰열 x₁,…,x\_T의 확률은 확률의 연쇄법칙에 따라 p(x₁)×p(x₂\|x₁)×…×p(x\_T\|x₁,…,x\_(T−1))로 쓸 수 있다. 실제 모델은 이 조건부확률을 신경망의 출력으로 근사한다.

문장 전체를 하나의 정답 범주로 외우는 것이 아니라, 각 위치에서 어휘 전체에 대한 분포를 만드는 것이다.


이 조건부확률을 배우는 목표와 사람이 질문에 답하는 제품 동작은 같지 않다. 기본 사전학습은 텍스트의 연속을 예측하는 능력을 만들고, 대화 형식·지시 응답·선호도 자료를 이용한 후속 학습은 어떤 상황에서 어떤 출력을 선호할지 바꾼다. 도구를 실제로 실행하는 동작은 모델 바깥의 프로그램이 수행한다. 이 구분은 L08의 Agent 구조로 이어진다.

### 토큰별 확률에서 문장 손실까지 계산하기

세 정답 토큰의 조건부확률이 0.8,0.5,0.25라면 전체 확률은 0.1이다. 음의 로그우도 합은 −ln(0.1)≈2.30259, 토큰당 평균은 약 0.76753nat다. perplexity는 exp(0.76753)≈2.15443이다.

```py
import math
probabilities = [0.8, 0.5, 0.25]
mean_nll = -sum(math.log(p) for p in probabilities)/len(probabilities)
assert math.isclose(math.exp(mean_nll), 10**(1/3))
```

토큰당 평균을 낼 때 어떤 토큰을 분모에 포함했는지 확인한다. tokenizer·평가 corpus·문맥 길이·mask가 다르면 perplexity 숫자를 직접 비교하기 어렵다. **낮은 다음 토큰 손실은 업무 정답률이나 사실성 전체를 보장하지 않는다.**

## 토큰화: 문자를 모델이 처리할 기호로 바꾸기

### 개념과 작동 원리

토큰화는 문자열을 정수 ID 열로 바꾸는 별도 단계다. 토큰이 항상 단어 하나인 것은 아니다. 단어 일부·문자·바이트 조각이 될 수 있고, 같은 문자열도 tokenizer에 따라 다른 길이가 된다. 모델의 embedding 행렬은 어휘 크기 V와 모델 차원 d에 대해 V×d이고, ID는 이 행렬에서 해당 행을 찾아 벡터로 바뀐다.

BPE의 직관은 자주 함께 나타나는 작은 조각을 합쳐 더 큰 조각을 만드는 것이다. 장난감 자료의 토큰열이 \[a,b,a,b\]이고 쌍 (a,b)가 자주 나타나면 새 기호 ab를 만들고 \[ab,ab\]로 바꿀 수 있다. 실제 tokenizer 학습은 많은 텍스트와 병합 규칙·바이트 표현·특수 토큰을 다루지만, 이 예는 어휘와 길이 사이의 관계를 보여준다. 토큰화의 학습과 언어모델 가중치의 학습은 서로 다른 과정이다.

문자열을 ID로 바꾸는 encode와 ID를 문자열로 되돌리는 decode가 필요하다. 공백·유니코드·특수 토큰 처리 규약이 다르면 기대한 복원이 달라질 수 있다.

대화에서는 사용자·도우미 역할의 시작·종료를 나타내는 형식도 중요하다. 같은 문장을 넣어도 모델이 학습한 chat template와 다른 구분자로 감싸면 다른 입력이다.

모델 이름만 저장하지 않고 tokenizer revision과 template를 함께 관리해야 한다.


### 글자·바이트·토큰 예산 구분하기

한글 '가'는 Python 문자열 길이로 1이지만 UTF-8로는 3바이트다. 모델 토큰 수는 tokenizer 규칙을 적용해야 알 수 있으며 글자 수나 바이트 수만으로 확정하지 않는다.

| 단위 | 이 예의 의미 | 비용·제약과 연결할 때 |
|---|---|---|
| 문자 | 문자열을 이루는 기호 단위 | 사용자 표시 길이와도 구현 차이 가능 |
| 바이트 | 인코딩된 저장·전송 단위 | UTF-8 등 인코딩 명시 |
| 토큰 | 모델 어휘의 기호 ID | tokenizer·특수 토큰 규칙 명시 |

문맥 한도가 8192토큰이고 입력 전체가 6500, 출력 예약이 1024라면 나머지는 668토큰이다. 입력 전체에는 시스템 설명·도구 schema·검색 자료·이전 대화도 포함할 수 있다. 실제 모델의 입력·출력 한도와 계산 방식은 별도 계약을 확인한다.

## 다음 토큰 정답은 입력을 한 칸 이동해 만든다

### 개념과 작동 원리

토큰열 \[A,B,C,D\]를 보자. 입력 \[A,B,C\]에서 각 위치의 정답은 \[B,C,D\]가 된다.

첫 위치는 A를 보고 B를, 두 번째는 A,B를 보고 C를, 세 번째는 A,B,C를 보고 D를 예측한다. 훈련 텐서에는 실제 토큰을 동시에 넣을 수 있지만 causal mask가 미래 위치를 가린다.

이를 teacher forcing을 사용한 자기회귀 학습으로 볼 수 있다. 생성 시에는 아직 실제 다음 토큰이 없으므로 자신의 출력을 다음 입력에 붙여야 한다.


배치의 길이가 T이고 어휘가 V라면 logits는 보통 B×T×V다. 정답은 B×T의 정수 ID다. 토큰별 교차엔트로피를 평균할 때 padding이나 학습에서 제외할 위치는 mask로 빼야 한다. 다음 코드는 이미 causal model을 정의했고 PAD\_ID가 정해져 있다는 가정 아래 정답 이동을 드러낸다.

```py
inputs = tokens[:, :-1]
targets = tokens[:, 1:]
logits = model(inputs)
loss = torch.nn.functional.cross_entropy(
    logits.reshape(-1, logits.size(-1)),
    targets.reshape(-1), ignore_index=PAD_ID
)
```

이 코드는 PAD와 EOS의 ID가 다르고 오른쪽 padding을 사용한다고 가정한다. 둘이 같은 ID라면 토큰 값만으로 제외하지 말고 실제 padding 위치를 이용해 labels를 −100 등 별도 무시값으로 바꿔야 종료 토큰의 학습까지 지우지 않는다.

왼쪽 padding 등에서는 padding이 유효 입력의 attention에 섞이지 않도록 모델이 요구하는 attention\_mask도 별도로 제공해야 한다. 첫 줄은 각 시퀀스의 마지막 토큰을 입력에서 제외한다.

두 번째 줄은 첫 토큰을 제외해 한 칸 뒤 정답을 만든다. 세 번째 줄의 모델 내부에서 causal mask가 적용돼야 한다.

네 번째 이후는 B×T개의 위치를 표본 축으로 펼치고 V를 클래스 축으로 남긴다. 정답도 같은 순서로 펼치며 padding ID의 손실은 무시한다.

대화 SFT에서 사용자 입력 부분까지 제외하려면 별도의 loss mask·ignore label이 추가로 필요하다. 이 코드 자체가 데이터 누수나 대화 형식을 자동 검증해 주지는 않는다.


토큰 정답에 준 확률이 \[0.5,0.25\]라면 평균 음의 로그우도는 −(ln0.5+ln0.25)/2=(ln2+ln4)/2=1.0397이다. perplexity는 그 지수이므로 e\^1.0397=√8≈2.828이다. 정답 확률의 기하평균 0.3536의 역수와 같다. perplexity가 작으면 그 평가 토큰열에 더 높은 평균 확률을 부여했다는 뜻이지만, 다른 tokenizer·평가 자료의 수치를 그대로 비교하거나 사실 정확성과 동일시할 수는 없다.

### shifted label과 loss mask는 다른 조작

입력이 [A,B,C]이고 다음 토큰 정답이 [B,C,D]라면 causal mask는 각 위치에서 볼 수 있는 입력을 제한한다. loss mask는 어느 정답 위치의 손실을 합산할지 정한다.

| 위치 | 볼 수 있는 입력 | 정답 | 손실 사용 예 |
|---|---|---|---|
| 1 | A | B | 문맥 영역이면 제외 가능 |
| 2 | A,B | C | 응답 영역이면 포함 |
| 3 | A,B,C | D | 응답 영역이면 포함 |

첫 위치의 loss를 제외한다고 그 위치 입력이 뒤 위치에서 사라지는 것은 아니다. padding도 문맥·attention·loss에서 어떤 역할인지 각각 확인해야 한다.

teacher forcing에서는 실제 앞 토큰을 조건으로 병렬 학습하지만 생성에서는 앞서 모델이 선택한 토큰을 조건으로 이어 간다. **학습 손실을 계산한 조건과 실제 생성 경로의 조건이 다를 수 있다.**

## 사전학습·SFT·선호도 정렬의 차이

### 개념과 작동 원리

사전학습은 대규모 자료의 언어 패턴과 지식을 다음 토큰 예측 등으로 학습한다. SFT는 입력 지시에 대한 바람직한 응답 예제를 사용해 그 응답의 확률을 높인다. 역할 구분자와 EOS를 포함한 대화 형식, 응답이 끝나는 위치, 어떤 토큰에 손실을 적용할지가 모델 동작에 영향을 준다. 문장 몇 개를 추가했다고 외부 데이터베이스처럼 정확한 사실 저장·갱신이 보장되는 것은 아니다.

선호도 정렬은 같은 질문에 대해 어떤 응답을 더 선호하는지에 관한 신호를 이용한다. 보상모델과 강화학습을 쓰는 구성도 있고, 선호 응답 쌍을 직접 목적함수에 넣는 방식도 있다. 모든 정렬이 같은 rollout·보상 파이프라인을 필요로 하는 것은 아니다. SFT의 ‘예제 응답을 따라가기’와 선호도 학습의 ‘응답 사이 상대적 선호 반영’을 구분하면 각 데이터가 무엇을 가르치는지 이해하기 쉽다.

평가 자료가 학습 자료와 중복되거나 정답 해설이 이미 들어갔다면 점수가 높아도 새 문제에 대한 능력을 과대평가할 수 있다. 문장 단위 중복뿐 아니라 동일 문제의 변형·번역도 고려한다. 좋은 토큰 예측 점수와 좋은 도구 사용·사실 응답 성능은 겹치는 부분이 있지만 같은 시험은 아니다.

### SFT와 선호 학습의 정답 단위 비교

| 단계·방법 | 학습 자료의 대표 형태 | 직접 올리려는 것 |
|---|---|---|
| 사전학습 | 텍스트 토큰열 | 관측된 다음 토큰의 우도 |
| SFT | 입력과 바람직한 응답 | 응답 토큰의 우도 |
| 선호 학습 | 같은 입력의 선호·비선호 응답 | 선호에 맞는 상대적 응답 경향 |

DPO의 한 손실은 $-\log\sigma(\beta\Delta)$이고, $\Delta=\log(\pi_\theta(y_w|x)/\pi_{ref}(y_w|x))-\log(\pi_\theta(y_l|x)/\pi_{ref}(y_l|x))$다. 선호 응답의 현재·기준 비율이 2, 비선호 응답의 비율이 0.5이고 β=1이면 Δ=ln(4), σ(Δ)=0.8, 손실은 약 0.22314다.

여기서 비교하는 것은 **기준 모델 대비 상대 변화**다. 선호 자료의 품질·범위가 실제 사용자 목적을 대변하는지도 중요하다. SFT·사람의 선호 피드백을 결합한 흐름은 [InstructGPT 원 논문](https://arxiv.org/abs/2203.02155)도 참고한다. 선호도가 높다는 사실을 모든 문장의 객관적 참으로 바꾸어 읽지 않는다. [DPO 원 논문](https://arxiv.org/abs/2305.18290)의 목적식과 가정을 참고한다.

## LoRA와 양자화는 서로 다른 비용을 줄인다

### 개념과 작동 원리

일반 미세조정은 선택한 전체 가중치를 갱신한다. LoRA는 W에 대한 변화 ΔW를 낮은 rank의 곱 BA로 표현한다. W가 d\_out×d\_in이고 x가 d\_in×1이면 Wx와 BAx 모두 d\_out×1이어야 한다. A는 r×d\_in, B는 d\_out×r이다. r이 작으면 추가 학습 파라미터 수 r(d\_in+d\_out)가 전체 d\_outd\_in보다 작다.

d\_in=d\_out=4096,r=8이면 전체 가중치는 4096²=16,777,216개지만 A와 B는 8×4096+4096×8=65,536개다. 비율은 65,536/16,777,216=1/256≈0.39%다. 이는 한 가중치 행렬에 대한 예시이지 모델 전체 학습 메모리가 0.39%가 된다는 뜻은 아니다. base 가중치·활성값·선택한 optimizer·저장해야 하는 중간값이 여전히 필요하다.

양자화는 가중치나 활성값 등을 더 적은 비트로 표현하는 방법이다. 16bit 대신 4bit면 이상적인 packed 가중치 저장량은 1/4이지만 scale·zero point·그룹 metadata와 일부 높은 정밀도 연산이 추가될 수 있다. 표현이 작아진다는 사실과 빠르게 계산할 수 있다는 사실은 다르다.

하드웨어·커널이 해당 형식을 효율적으로 지원해야 하고, 숫자 근사로 인한 품질 변화도 평가해야 한다. QLoRA처럼 양자화된 base와 adapter 학습을 결합한 방법도 두 역할을 나눠 이해한다.


### trainable parameter와 전체 모델 저장량 구분

1024×1024 가중치 하나는 1,048,576개 파라미터다. rank 8의 LoRA A·B는 8×1024+1024×8=16,384개로 이 행렬의 약 1.5625%다. 여기서는 스케일 계수와 절편을 제외해 센다.

| 감소시킬 대상 | 대표 방법 | 남는 비용 |
|---|---|---|
| 학습할 가중치 수 | LoRA 같은 저차원 갱신 | 기본 모델 저장·연산·일부 활성값 |
| 가중치 표현 바이트 | 양자화 | scale·메타데이터·커널 제약 |
| 긴 입력의 활성 메모리 | 별도 실행·학습 전략 | 가중치 크기만 줄여도 해결 안 될 수 있음 |

기본 행렬을 동결해도 그 계산이 없어지는 것은 아니다. 양자화 4bit라고 모든 활성값·gradient·optimizer 상태까지 4bit가 되는 것도 아니다. [LoRA 원 논문](https://arxiv.org/abs/2106.09685)의 동결 가중치와 학습 저랭크 행렬을 구분한다.

## 디코딩은 확률에서 실제 토큰을 선택하는 규칙이다

### 개념과 작동 원리

greedy decoding은 가장 높은 확률의 토큰을 고른다. 샘플링은 분포에 따라 토큰을 뽑는다. temperature T를 사용할 때는 보통 logits를 T로 나누고 softmax한다. z=\[0,ln3\]에서 T=1이면 \[0.25,0.75\]이고, T=0.5이면 \[0,ln9\]를 softmax해 \[0.1,0.9\]다. 낮은 양의 온도는 분포를 뾰족하게 만들지만 내용이 더 참이 되도록 사실 검증하는 장치는 아니다.

Top-k는 높은 확률 k개 후보를 남기고 다시 정규화한다. Top-p는 확률 내림차순에서 누적 확률이 p에 도달하는 최소 후보 집합을 남긴다.

\[0.6,0.25,0.15\]에서 p=0.8이면 첫 두 후보의 합 0.85가 기준을 넘으므로 두 개를 남기고 \[0.6/0.85,0.25/0.85\]≈\[0.706,0.294\]로 정규화한다. EOS, 최대 출력 토큰, stop sequence는 생성 중단 조건이다.

이런 규칙은 모델 가중치를 다시 학습하는 것과 다르다.


### temperature와 top-p가 바꾸는 분포

logits [ln(9),0]이면 T=1에서 확률 [0.9,0.1], T=2에서는 [0.75,0.25]다. 양의 T를 바꾸면 정규화된 상대 확률이 달라지지만, 원래 logit의 순서는 바뀌지 않는다.

```py
import math
logits = [math.log(9), 0.0]
weights = [math.exp(z/2) for z in logits]
p = [v/sum(weights) for v in weights]
assert math.isclose(p[0], 0.75)
```

top-p=0.8을 [0.6,0.25,0.1,0.05]에 적용해 누적 확률이 기준에 닿을 때까지 남기는 규칙이면 앞 두 토큰이 남는다. 재정규화 후 확률은 [12/17,5/17]이다.

**greedy는 현재 한 단계의 최댓값 선택**이다. 첫 선택지가 A=0.6, B=0.4이고 A 뒤 후보 10개가 모두 0.1, B 뒤 최상위 후보가 0.9라고 하자. greedy가 고른 A 경로의 확률 0.6×0.1=0.06보다 B 경로의 0.4×0.9=0.36이 크다. 현재 가장 높은 확률을 골랐다고 전체 토큰열의 확률이나 업무 품질도 최대라는 뜻은 아니다.

## Prefill·Decode와 KV cache

### 개념과 작동 원리

Prefill은 이미 주어진 입력 토큰열을 처리하는 단계다. Decode는 새 토큰을 생성하면서 이어가는 단계다. 과거 토큰의 key·value는 causal 구조에서 다음 토큰을 만든다고 바뀔 필요가 없으므로 저장해 재사용할 수 있다. 이것이 KV cache다. 캐시는 이전 계산 결과를 재사용하는 장치이며 대화 내용을 사람이 이해하는 방식의 장기 기억과 같은 개념은 아니다.

일반적인 dense decoder에서 cache 원소 수의 근사는 다음과 같다.

$$
N_{\mathrm{KV}}=2BTLH_{\mathrm{KV}}D_{\mathrm{head}}
$$

2는 key와 value, B는 batch, T는 저장한 토큰 수, L은 층수, H\_KV는 KV head 수, D\_head는 head 차원이다. 원소당 byte 수 s를 곱하면 저장량이 된다. GQA에서는 query head 수와 KV head 수가 다르므로 query head를 그대로 대입하면 잘못 계산할 수 있다.

32층, KV head 8개, head 차원 128, FP16의 2byte라는 예를 쓰자. 토큰 하나·시퀀스 하나의 cache는 2×32×8×128×2=131,072byte=128KiB다.

길이 2048이면 131,072×2048=268,435,456byte=256MiB, 8192이면 1,073,741,824byte=1GiB다. 같은 길이 시퀀스 4개를 동시에 두면 대략 4GiB다.

이 식은 가중치·활성값·임시 버퍼·allocator 여유 공간을 제외한 단순 cache 계산이다. Sliding-window·압축·특수 구조·정밀도에 따라 실제는 달라진다.


![단순 KV 저장량 공식 2×층수×배치×토큰수×KV head수×head차원×원소 byte를 적용했습니다. 가중치·활성값·할당기 비용은 별도입니다.](/figures/L07.svg)

단순 KV 저장량 공식 2×층수×배치×토큰수×KV head수×head차원×원소 byte를 적용했습니다. 가중치·활성값·할당기 비용은 별도입니다.

그림의 기울기는 토큰 하나가 추가될 때 늘어나는 cache를 뜻한다. 같은 구조에서 batch를 4배로 하면 같은 길이의 y값도 4배가 된다.

이는 표준 dense attention score의 n² 비용과 다른 관계다. 학습 중 score·활성값 메모리와 생성 중 저장하는 KV cache를 한 공식으로 혼동하지 말자.

그림이 나타내는 것은 위 32층·8 KV head·128차원·FP16 가정의 계산량이며 측정한 GPU 최대 메모리가 아니다.


첫 토큰까지의 시간 TTFT에는 입력 처리와 대기 등이 포함되고, 토큰 사이 시간은 decode 속도와 관련된다. 초당 토큰 수, 전체 요청 처리량, 사용자 응답 시간은 서로 다른 지표다. 긴 입력·동시 요청·batch 구성에 따라 각각 다르게 변할 수 있다. 큰 context window를 지원한다는 것이 그 길이를 비용 없이 사용한다는 뜻은 아니다.

### cache 용량은 길이·배치·KV head 수에 비례한다

일반적인 저장 모형에서 KV 원소 수는 $2BLnh_{KV}d_h$다. 2는 key와 value, B는 배치, L은 층 수, n은 저장 토큰 수, h_KV는 KV head 수, d_h는 head 차원이다.

B=2,L=2,n=10,h_KV=2,d_h=4이고 원소당 2바이트면 1280바이트다. query head 수가 다르더라도 KV가 공유되는 구성에서는 query head 수를 그대로 h_KV에 넣으면 안 된다.

| 단계 | 계산 재사용 | 길이가 늘 때 |
|---|---|---|
| prefill | 주어진 문맥의 K·V 구성 | 입력 처리·저장량 증가 |
| decode | 과거 K·V를 다시 사용 | 새 query가 읽을 과거가 증가 |

캐시는 모델 가중치를 갱신하는 학습 기억과 다르며, 세션·모델·위치·입력의 호환 조건도 필요하다. [공식 cache 설명](https://huggingface.co/docs/transformers/cache_explanation)과 연결해 읽는다.

**복습 문제:** 다른 조건이 같고 저장 토큰 수만 2배면 이상적 KV 저장량은?

<details><summary>풀이</summary>

2배다. 다만 전체 GPU 메모리에는 고정 가중치·활성값·할당 여유가 함께 있어 전체 사용량도 정확히 2배가 되는 것은 아니다.

</details>

## 핵심 정리

LLM은 tokenizer가 만든 기호열의 조건부확률을 학습한다. 훈련에서는 이동한 정답과 causal mask를 사용하고 생성에서는 자신의 출력을 이어 붙인다.

SFT·선호도 정렬·디코딩 규칙은 서로 다른 단계의 동작을 바꾼다. LoRA는 갱신 파라미터를, 양자화는 수치 표현 비용을 줄이지만 전체 메모리를 단순 비율로 줄이지는 않는다.

KV cache는 과거 key·value를 재사용하며 길이·batch·층수·KV head에 따라 증가한다. 품질·지연·메모리를 해석할 때 모델 revision·tokenizer·template·생성 설정까지 함께 고정해야 한다.


## 복습 문제와 풀이

**1. 다음 토큰 정답 확률이 \[0.5,0.5\]라면 평균 음의 로그우도와 perplexity는?**

<details>
<summary>풀이 보기</summary>

평균 음의 로그우도는 −(ln0.5+ln0.5)/2=ln2≈0.693이다. perplexity는 e\^ln2=2다. 확률 0.5 두 개를 단순 평균한 0.5의 역수도 이 특별한 경우에는 같지만, 일반적으로는 기하평균을 써야 한다.

</details>

**2. 본문의 cache 가정에서 길이 4096, batch 2의 FP16 KV cache는?**

<details>
<summary>풀이 보기</summary>

시퀀스당 토큰 1개가 128KiB다. 4096개는 128×4096KiB=524,288KiB=512MiB이고 시퀀스 2개는 1024MiB=1GiB다. 모델 가중치 등은 별도다.

</details>

**3. LoRA rank를 8에서 16으로 바꾸면 base 가중치 저장량과 adapter 파라미터 수는 어떻게 변하는가?**

<details>
<summary>풀이 보기</summary>

같은 대상 행렬에서 base 가중치 크기는 바뀌지 않는다. adapter 파라미터 r(d\_in+d\_out)는 r에 선형 비례하므로 두 배가 된다. 전체 메모리가 두 배 또는 그대로라고 단정하려면 활성값·optimizer·실행 구성을 더 알아야 한다.

</details>
